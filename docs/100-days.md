# 《洋流》市府上任 100 天：分區驗證

> 這份文件只放**市府上任第一天就能開始、100 天內真的做得到**的方案。分工、時程與金額都是團隊的估計。
>
> 做 App、帳號和後端兌換的完整版，要等補助核定或合作簽署才能開始，也要多個局處配合，不可能從上任第一天起算，所以另外放在 [docs/full-version.md](full-version.md)，當作驗證之後的下一步。

## 一句話

上任第一天，就用**現在已經能玩的手機網頁版**，選一個區、結合少數店家，讓市民真的走出門玩。100 天後用數據回答一件事：**這個做法值不值得擴大到全市。**

這和政見「先從代表性路線做示範，再逐步擴大到不同主題與區域」的推動藍圖一致。

## 怎麼判斷「第一天就能開始」

我們用四個條件重新檢視每個方案，四個都符合才放進這份文件：

| 條件 | 為什麼 |
|---|---|
| 不用等新的開發 | 上任第一天能拿出來的，只有已經做好的手機網頁版 |
| 不用等經費審查 | 補助審查、編列預算都要好幾個月，經費必須是團隊和商圈當下就能出的 |
| 不靠多個局處配合 | 新團隊剛上任，局處還在交接；只能依賴一個窗口，甚至一開始完全不依賴 |
| 不需要申請許可或第三方檢測 | 公有地立牌許可、資安檢測都要排程，100 天內不保證拿得到 |

用這四個條件看，原本規劃的「100 天內完成 App」不符合（要等經費、要做第三方資安檢測、要跨局處），所以移到 [完整版規劃](full-version.md)。

## 兩個可行方案

| | 方案一：一區驗證 | 方案二：兩區驗證 |
|---|---|---|
| 做什麼 | 在一個區做 8–10 個點位、結合 3–5 家店家 | 方案一，再把同一套做法複製到第二個區 |
| 區域 | 信義區象山一帶（四獸山步道＋信義商圈） | 加上萬華或大龍峒（遊戲第二階已經有這兩區的城市故事） |
| 回答什麼問題 | 這個做法有沒有人玩、能不能帶人進商圈 | 再加上：換一個區要花多少時間和錢，能不能推到全市 |
| 費用（估計） | **約 45–80 萬** | **約 70–125 萬** |
| 適合 | 先確認概念 | 想在 100 天後直接拿數據規劃全市擴大 |

**建議先做方案一**，第 30 天時看進度，順利就加上第二區，變成方案二。

## 範圍（兩個方案共通）

| | 做 | 不做（留給完整版） |
|---|---|---|
| 平台 | 現有手機網頁版，掃 QR Code 就玩 | 原生 App |
| 點位 | 每區 8–10 個公共、好走的點位 | 需要許可的步道立牌 |
| 店家 | 每區 3–5 家願意參與的店家，提供小額優惠或贈品 | 大規模招募、店家後台 |
| 帳號與兌換 | 不做帳號；用現有的兌換畫面（會動的圖案＋當下時間＋用過蓋章），店家用登記表記錄兌換次數 | 伺服器紀錄、一次性兌換碼、核銷系統 |
| 防偽 | 優惠設計成小額，接受小規模下的少量風險 | 完整防偽 |
| 內容 | 中文；英文用 AI 初譯、人工快速校對 | 日韓語、文化局正式審訂 |
| 安全 | 人工確認步道狀況，只選白天的公共點位 | 即時路況串接 |
| 個資 | 不收集個資，紀錄只存在玩家手機 | 帳號與雲端同步 |

## 時程

| 期間 | 方案一 | 方案二另外加上 |
|---|---|---|
| 第 1–14 天 | 選定點位、拜訪商圈發展協會和店家、確認優惠 | |
| 第 15–45 天 | 把 Demo 點位換成新區域；用 AI 起草故事與問答、人工查證；現場校正座標；製作店家物品、店內 QR Code 立牌 | |
| 第 30 天 | 檢查點：決定要不要加第二區 | 選定第二區、開始拜訪店家 |
| 第 46–90 天 | 開放市民試玩；辦 2 場週末走讀；店家開始兌換 | 第 46–70 天準備第二區（沿用現有城市故事）；第 70 天起開放，辦 1–2 場走讀 |
| 第 91–100 天 | 整理數據與問卷，寫驗證報告 | 比較兩區的數據和複製成本 |

## 可行性檢視：還是可能卡住的地方

| 風險 | 調整方式 |
|---|---|
| 市府窗口在上任初期還沒指定 | 前 14 天不依賴市府，團隊直接找商圈發展協會；窗口確定後再請市府協助推廣 |
| 14 天內找不到店家 | 首批只要 3 家；找不到時先用景點和走讀活動開始，店家在第 45 天前補上 |
| 現場座標不準 | 每個點位都由團隊實地走過、校正，不只靠地圖資料 |
| 天候（颱風、豪雨） | 走讀活動預留備用日期；點位都在白天的公共區域 |
| 玩家人數太少 | 結合走讀活動、商圈和里辦公處的社群宣傳；問卷同時問「為什麼沒來」 |
| 經費 | 方案一的規模可以由團隊自籌加上商圈贊助，不等任何審查 |
| 兌換有人作弊 | 優惠設計成小額；店家登記表可以看出異常次數 |

## 用 AI 工具加速

《洋流》的 MVP 本身就是大量使用 AI 工具做出來的（見 README 的 AI 工具表）。分區驗證也用同樣的方式，**AI 負責起草和重複性工作，人負責判斷、查證和實地走過**：

| 工作 | AI 怎麼幫忙 | 人要做的 |
|---|---|---|
| 換點位與程式調整 | 用 AI 程式助理（例如 Claude Code）改點位資料、調整介面、跑自動化測試 | 程式審查、手機實測 |
| 地點故事與問答 | 從開放資料與文獻整理出故事和問答草稿 | 查證史實、保留在地觀點 |
| 翻譯 | AI 初譯英文 | 人工校對 |
| 物品美術 | AI 生成店家物品概念圖，維持 Roblox 方塊風 | 美術把關、統一風格 |
| 數據整理 | 整理問卷和兌換登記表 | 判斷結論、寫建議 |

不能省的是實地踏查、校正座標和跟店家當面溝通。

## 分工

分區驗證規模小，不需要跨多個局處：

| 角色 | 負責 |
|---|---|
| 團隊 | 選點位、改遊戲內容與程式、現場校正、製作物品與立牌、辦走讀活動、整理數據與驗證報告 |
| 商圈發展協會 | 媒合願意參與的店家 |
| 店家 | 提供小額優惠或贈品、登記兌換次數、回饋意見 |
| 區公所、里辦公處 | 在地宣傳、提供社區活動場地（有意願就合作，不是前提） |
| 市府（一個窗口，例如觀光傳播局或產業發展局商業處） | 用市府管道推廣走讀活動（窗口確定後加入，不是前提） |

## 費用（新台幣，估計）

| 項目 | 方案一 | 方案二另外加上 |
|---|---|---|
| 新區域的點位內容與故事（AI 起草、人工查證） | 10–15 萬 | 5–10 萬（沿用現有城市故事） |
| 程式調整（AI 輔助） | 15–30 萬 | 5–10 萬 |
| 主機（靜態網站） | 約 0–1 萬 | — |
| 店家物料與店內 QR Code 立牌 | 5–10 萬 | 5–10 萬 |
| 週末走讀活動 | 5–10 萬 | 5–10 萬 |
| 問卷與數據整理 | 3–5 萬 | 2–5 萬 |
| 專案協調 | 5–10 萬 | 3–5 萬 |
| **合計** | **約 45–80 萬** | **再加約 25–45 萬，合計約 70–125 萬** |

- 經費由**團隊自籌加上商圈贊助**，不等補助或預算審查。店家的優惠由店家自行負擔。
- 因為不需要帳號和後端，沒有固定的年度伺服器費用。
- 驗證期間就可以開始準備補助申請，100 天後用驗證報告去申請，作為完整版的經費。

## 怎麼算成功

| 問題 | 怎麼看 |
|---|---|
| 大家會不會因為遊戲走出門？ | 到訪人數、完成四獸靈門的比例、走路距離 |
| 會不會帶人進商圈？ | 各店家的兌換次數、店家主觀感受 |
| 有沒有認識在地文化？ | 故事問答的完成率、試玩問卷（是否第一次走這條步道、是否記得某個故事） |
| 會不會再回來？ | 回訪人數、有沒有人問下一區 |
| 能不能複製？（方案二） | 第二區從開始到開放花了幾天、多少錢 |

這些指標都用匿名統計，不保存玩家的移動軌跡。

## 驗證之後

- **數據好**：用驗證報告申請補助、和市府簽合作備忘錄，進入 [完整版](full-version.md)（App＋帳號＋後端兌換，建置約 340–570 萬、每年營運約 95–200 萬），再擴大到其他區域。
- **數據普通**：調整玩法、點位或店家合作方式，換一個區再驗證一次。
- **數據不好**：停在這裡，損失只有幾十萬，不會浪費大型預算。
