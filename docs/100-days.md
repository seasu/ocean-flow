# 《洋流》市府上任 100 天落地範圍

> 這份文件整理 100 天內可以做到的範圍，讓預算有清楚的對應。局處分工、時程與金額都是**團隊的估計**，需要與各局處確認。

## 一句話

100 天內，先把現在的 MVP 做成**原生 App，帶著一條真的能走、能玩、能在商圈兌換的示範路線進入實地測試**：從象山登山觀光中心出發，串起四獸山步道、信義商圈和台北城市故事。App 正式上架商店、其他區域和多城市擴展，留到 100 天之後。

這和政見「先從代表性路線做示範，再逐步擴大到不同主題與區域」的推動藍圖一致。

## 範圍總覽

| | 100 天內會做 | 100 天後再做 |
|---|---|---|
| 路線 | 1 條示範路線：象山登山觀光中心＋四獸山＋信義商圈，加上現有 7 個台北城市故事 | 北劍潭、南貓空兩座登山中心的路線；四大主題文化徑的其他區域 |
| 平台 | 開發 iOS／Android App（沿用現有遊戲程式，用跨平台方式包裝），加上背景定位和手機內建計步器；用 TestFlight 和 Google Play 封閉測試發給測試者，進入實地測試。手機網頁版持續開放，當作不必下載的體驗入口 | App 正式上架 Apple App Store、Google Play（審核時間與結果不可控，不列入 100 天承諾） |
| 帳號與紀錄 | 簡易帳號登入，靈光、成就、物品存在伺服器，換手機也還在 | 串接市府「台北通」 |
| 商圈信物 | 首批 5–10 家合作店家；一次性 QR Code 兌換、店家用手機網頁掃碼核銷 | 完整店家後台（自訂優惠、數量、期限）與兌換報表 |
| 防偽 | App 計步與 GPS 交叉比對、偵測模擬定位；伺服器保存紀錄、一次性兌換碼 | 藍牙 beacon 等現場驗證、越獄／root 偵測 |
| 內容 | 示範路線新增的地點與故事；文化局審訂；中英兩語 | 日韓語；內容後台，讓局處和商圈自己更新 |
| 安全 | 安全評估；接上步道封閉資料，封閉時自動停用該點 | 天候與夜間自動提醒 |
| 檢測 | 資安、個資與網站無障礙檢測 | 依檢測結果持續改善 |
| 數據 | 匿名統計各點到訪人數與兌換次數 | 給市府與商圈的成效儀表板 |

## 為什麼選象山這條路線

- 政見規劃的三座登山觀光中心裡，「東象山」串的是信義商圈和台北 101，商圈、交通和觀光客都最多。
- 遊戲第一階本來就是四獸山（象、虎、豹、獅），角色、戰鬥、故事都能直接沿用，只要把 Demo 用的會場周邊點位，換成步道口和商圈的真實地點。
- 捷運象山站到登山口的距離短，好走、好推廣，也方便規劃「最後一哩路」。

| 工務局大地工程處 | 四獸山步道資料、路況與封閉公告、步道上的安全點位與標示 |

## 需要的資料

- 臺北旅遊網景點 Open API（已接上）
- 四獸山親山步道路線、出入口與里程（大地工程處）
- 步道即時路況與封閉公告
- 文化資產／古蹟清單與座標（文化局）
- 示範路線各點位的實地 GPS 座標與照片（現場踏查）
- 首批合作店家名單與優惠內容（商業處、商圈發展協會）

## 100 天時程

| 期間 | 工作 | 產出 |
|---|---|---|
| 第 1–30 天 | 確認主責局處、資料授權與合作商圈；選定示範路線點位；安全評估；設計 App、帳號與兌換的後端；申請 Apple、Google 開發者帳號 | 路線與點位清單、店家名單、系統設計 |
| 第 31–60 天 | 現場踏查校正座標、拍照；新地點的故事與問答撰寫、文化局審訂、英文翻譯；開發 App（背景定位、計步）、帳號、紀錄與兌換核銷 | 可內部試玩的 App |
| 第 61–90 天 | 資安、個資與無障礙檢測；步道口、登山中心與合作店家設置 QR Code 立牌；用 TestFlight／Google Play 封閉測試邀請第一批市民試玩並修正 | 通過檢測的測試版 App |
| 第 91–100 天 | 擴大實地測試，搭配週末走讀活動；首批店家開始兌換「商圈信物」；開始匿名統計；同時送 Apple、Google 審核上架 | 實地測試數據、送審中的 App |

> App 上架要經過 Apple 和 Google 審核，時間和結果都不可控，所以 100 天的承諾是「App 完成並進入實地測試」，正式上架商店不列入 100 天內。測試期間，一般民眾仍可用手機網頁版體驗。

## 三種方案比較

| | 方案 A：只做手機網頁 | 方案 B：只做 App | 方案 C：網頁＋App（建議） |
|---|---|---|---|
| 怎麼玩 | 用瀏覽器開網址就能玩，可加到主畫面 | 到 App Store／Google Play 下載 | 想試玩的人開網頁；要正式走路線、集章、兌換的人下載 App |
| 100 天開發費 | **約 270–440 萬** | **約 400–660 萬** | **約 430–710 萬** |
| 每年營運費 | **約 80–170 萬** | **約 100–210 萬** | **約 110–230 萬** |
| 100 天內可達成 | 正式上線 | App 完成、進入實地測試（上架商店時間不可控） | 網頁版正式上線；App 完成、進入實地測試 |
| 走路與定位 | 畫面關掉或切到背景，GPS 就停止，走路距離容易漏算；沒辦法讀手機的計步器 | 背景定位和手機內建計步器，記錄最準 | 網頁版同 A；App 版同 B |
| 防偽 | 難偵測模擬定位，商圈信物要靠現場 QR Code 等方式補強 | 可偵測模擬定位，交叉比對步數與 GPS | 兌換信物限定用 App，防偽同 B |
| 推播提醒 | iPhone 要先加到主畫面才收得到，支援度有限 | 完整支援（例如「附近有機緣」） | App 版完整支援 |
| 門檻 | 最低，不用下載，掃 QR Code 就玩 | 要下載安裝，部分人會因此放棄 | 先用網頁吸引人，再引導下載 App |
| 更新速度 | 改完立即生效 | 每次更新都要送審 | 網頁立即生效；App 要送審 |
| 適合 | 預算有限、先驗證大家願不願意走 | 重視紀錄準確與兌換防偽 | 想兼顧推廣的低門檻與兌換的可信度 |

方案 A 的費用不含 App 開發與 App 資安檢測，但多了以現場 QR Code 補強防偽的費用；方案 B 不需維護網頁版與做網站無障礙檢測；方案 C 兩邊共用同一套遊戲程式和後端，所以只比 B 多一點。

**建議方案 C**：手機網頁版的低門檻適合推廣、走讀活動和「靈界走走」，App 負責精準記錄走路和兌換商圈信物。下面的預算與年度營運成本都以方案 C 計算。

## 預算估計（新台幣，以方案 C 計算）

| 項目 | 內容 | 估計 |
|---|---|---|
| 內容 | 新地點故事與問答、文案審訂、攝影、中英翻譯 | 30–50 萬 |
| 遊戲擴充 | 示範路線的新地點、物品與商圈信物美術、介面調整 | 60–100 萬 |
| App 開發 | 跨平台包裝現有遊戲、背景定位與計步、iOS／Android 測試版發佈 | 120–200 萬 |
| 手機網頁版同步維護 | 讓同一套程式也能在網頁版執行、網頁版的測試與發佈 | 20–40 萬 |
| 帳號與後端 | 帳號登入、伺服器紀錄、一次性兌換碼、店家核銷頁 | 80–120 萬 |
| 雲端主機與開發者帳號 | 後端與資料庫；Apple、Google 開發者帳號 | 5–10 萬 |
| 檢測 | 資安（含 App）、個資與網站無障礙檢測 | 35–55 萬 |
| 實地測試 | 測試用手機、測試者招募與試玩活動 | 10–20 萬 |
| 現場立牌 | 步道口、登山中心與合作店家，約 15 處 | 15–30 萬 |
| 推廣活動 | 週末走讀、合作店家宣傳 | 30–50 萬 |
| 專案管理 | 跨局處協調、店家聯繫、測試營運 | 20–30 萬 |
| **合計** | | **約 430–710 萬** |

說明：
- 比 MVP 多出最多的是「App 開發」和「帳號與後端」。要精準記錄走路和到訪，需要 App 的背景定位與計步；商圈信物要換成實體優惠，紀錄就不能只存在玩家手機裡。
- App 沿用現有的遊戲程式，用跨平台方式包裝成 iOS 和 Android，不必從頭重寫兩套，所以能在 100 天內完成。
- 合作店家提供的優惠由店家自行負擔，不列入市府預算。

## 上線後的年度營運成本（由市府編列）

商圈信物的兌換要由後端伺服器檢驗（一次性兌換碼、防止重複使用、帳號與紀錄保存），所以上線後每年都會有固定的營運成本。這部分不屬於 100 天的開發預算，**應由市府（主責局處）每年編列**，或放在資訊局既有的雲端主機上。

| 項目 | 內容 | 每年估計 |
|---|---|---|
| 伺服器與資料庫 | 帳號、紀錄與兌換檢驗的後端；依使用人數調整 | 10–30 萬 |
| 開發者帳號 | Apple 開發者計畫年費（Google 只需一次性註冊費） | 約 0.5 萬 |
| 系統維運 | 資安更新、配合 iOS／Android 與瀏覽器新版本調整、故障處理 | 70–140 萬 |
| 內容更新 | 新增或更新地點、故事與商圈資料 | 20–40 萬 |
| 店家與玩家客服 | 兌換問題處理、店家聯繫 | 10–20 萬 |
| **合計** | | **約 110–230 萬／年** |

## 政府標案需要準備的資訊

如果市府要用標案委外執行，需求說明書（招標文件）通常要寫清楚下面這些項目。以下是團隊依政府採購的常見做法整理的建議，金額門檻和法規細節請以行政院公共工程委員會（工程會）和數位發展部的最新規定為準。

### 採購方式

| 項目 | 建議 |
|---|---|
| 採購類別 | 勞務採購（資訊服務） |
| 金額級距 | 開發預算約 270–710 萬元（依方案），超過公告金額、未達勞務查核金額（1,000 萬元），原則上要公開招標 |
| 決標方式 | 建議採最有利標或準用最有利標，由評選委員會評選，不只比價格；遊戲與內容品質比單純壓低價格重要 |
| 後續擴充 | 在招標公告和招標文件中先寫明「後續擴充」的期間與金額（例如上線後 2 年的營運維護），之後可依政府採購法第 22 條第 1 項第 7 款，以限制性招標延續給原廠商，不必每年重新招標 |
| 履約期限 | 決標次日起 100 日曆天內完成 App 並進入實地測試；上架商店不列入履約期限 |

### 資安、個資與無障礙

- **資通安全**：依資通安全管理法，委外廠商要符合機關的資安要求；不得使用危害國家資通安全的產品。App 依「行動應用 App 基本資安檢測基準」和 OWASP Mobile Top 10 委由專業機構檢測，後端做弱點掃描與滲透測試。
- **個人資料**：依個人資料保護法，只蒐集必要資料（帳號、到訪紀錄），不保存移動軌跡；契約要寫明廠商的個資保護義務、資料存放在國內，以及契約結束後的資料返還與刪除。
- **無障礙**：手機網頁版依「網站無障礙規範」做檢測；App 盡量符合，但核心玩法需要走路，範圍與限制見 README 的「MVP 的範圍與限制：無障礙」。
- **雲端**：優先使用市府既有的雲端或主機；若用商用雲端，資料要存放在國內機房。

### 智慧財產權

這一點要特別在招標前談清楚，因為《洋流》的世界觀、角色和美術是團隊既有的獨立 IP：

- **既有 IP**（世界觀、角色、四獸造型、遊戲核心程式）：著作權仍歸原創團隊，市府取得本案範圍內的**非專屬、永久使用授權**。
- **為本案新做的內容**（台北景點的故事與問答、拍攝的照片、示範路線資料）：著作財產權歸市府，或由雙方共有，方便市府日後以開放資料釋出或交給其他廠商延續。
- **原始碼**：交付市府保存，確保日後換廠商也能維護；授權範圍限本案用途。

### 廠商資格與評選

- 建議資格：具備手機 App 開發與上架經驗、遊戲開發實績，以及資安管理能力（例如通過 ISO 27001）。
- 建議評選項目與配分（參考）：

| 評選項目 | 配分 |
|---|---|
| 遊戲設計與內容品質（含在地文化呈現） | 30% |
| 技術架構、App 與後端可行性 | 20% |
| 資安與個資保護規劃 | 15% |
| 執行時程與團隊 | 15% |
| 商圈合作與推廣規劃 | 10% |
| 價格合理性 | 10% |

## 怎麼算成功

- 實地測試期間，示範路線的到訪人次與完成四獸靈門的人數
- 商圈信物的兌換次數與合作店家數
- 試玩問卷：玩家是否因此第一次走四獸山步道、是否更認識路線上的歷史

這些指標都用匿名統計，不保存玩家的移動軌跡。
