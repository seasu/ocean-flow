# 《洋流》100 天落地範圍與合作方式

> 這份文件整理 100 天內可以做到的範圍，讓預算有清楚的對應。局處分工、時程與金額都是**團隊的估計**，需要與各局處確認。
>
> 這份文件有兩條路：
> - **方案 D（上任第一天就開始）**：用現有的手機網頁 MVP，選一個區、找少數店家，先驗證概念。見下一節。
> - **方案 A／B／C（完整落地）**：100 天從經費與合作確定的那天起算（補助核定或合作備忘錄簽署），做到 App 進入實地測試。前置的提案、申請與協調時間另計。

## 一句話

100 天內，先把現在的 MVP 做成**原生 App，帶著一條真的能走、能玩、能在商圈兌換的示範路線進入實地測試**：從捷運象山站與象山步道口出發，串起四獸山步道、信義商圈和台北城市故事。App 正式上架商店、其他區域和多城市擴展，留到 100 天之後。

這和政見「先從代表性路線做示範，再逐步擴大到不同主題與區域」的推動藍圖一致。

## 方案 D：上任第一天開始的分區驗證

如果要從市府上任第一天就開始，最可行的做法不是一次做完 App 和完整後端，而是**拿現有的 MVP，在一個區、結合少數店家，先驗證這個概念行不行得通**。數據好，再投入方案 C。

### 為什麼可以第一天就開始

- 手機網頁版已經能玩：四獸靈門、城市故事、商圈物品、景點介紹與現世定位都做好了，不用等開發。
- 規模小、經費小，不必等補助審查或大型預算。
- 用 AI 工具改點位、寫故事草稿和調整程式，幾週內就能換到新的區。

### 範圍

| | 做 | 不做（留給方案 C） |
|---|---|---|
| 區域 | 選一個區，建議信義區象山一帶（四獸山＋信義商圈），約 8–10 個點位 | 其他區域 |
| 店家 | 3–5 家願意參與的店家，提供小額優惠或贈品 | 大規模店家招募 |
| 平台 | 現有手機網頁版，掃 QR Code 就玩 | 原生 App |
| 帳號與兌換 | 不做帳號；用現有的兌換畫面（會動的圖案＋當下時間＋用過蓋章），店家用簡單的登記表記錄兌換次數 | 伺服器紀錄、一次性兌換碼、店家核銷系統 |
| 防偽 | 接受小規模下的少量風險，優惠設計成小額 | 完整防偽 |
| 內容 | 中文；英文用 AI 初譯、人工快速校對 | 日韓語、文化局正式審訂 |
| 安全 | 只選公共、好走的點位；人工確認步道狀況 | 即時路況串接 |
| 個資 | 不收集個資，紀錄只存在玩家手機 | 帳號與雲端同步 |

### 時程

| 期間 | 工作 | 產出 |
|---|---|---|
| 第 1–14 天 | 選定區域與點位、拜訪店家、確認優惠 | 點位清單、3–5 家店家 |
| 第 15–45 天 | 把 Demo 點位換成新區域；用 AI 起草故事與問答、人工查證；現場校正座標；製作店家物品與立牌 | 可在新區域玩的版本 |
| 第 46–90 天 | 開放市民試玩；辦 2–4 場週末走讀；店家開始兌換 | 試玩與兌換數據 |
| 第 91–100 天 | 整理數據與問卷，決定是否擴大 | 驗證報告與下一步建議 |

### 要驗證什麼

| 問題 | 怎麼看 |
|---|---|
| 大家會不會因為遊戲走出門？ | 到訪人數、完成四獸靈門的比例、走路距離 |
| 會不會帶人進商圈？ | 各店家的兌換次數、店家主觀感受 |
| 有沒有認識在地文化？ | 故事問答的完成率、試玩問卷（是否第一次走這條步道、是否記得某個故事） |
| 會不會再回來？ | 回訪人數、有沒有人問下一區 |

### 分工

方案 D 規模小，不需要跨多個局處，分工可以簡化：

| 角色 | 負責 |
|---|---|
| 團隊 | 選點位、改遊戲內容與程式、現場校正、製作物品與立牌、辦走讀活動、整理數據與驗證報告 |
| 市府（一個窗口即可，例如觀光傳播局或產業發展局商業處） | 協助介紹商圈與店家、在市府管道推廣走讀活動 |
| 區公所、里辦公處 | 協助在地宣傳、提供社區活動場地 |
| 商圈發展協會 | 媒合 3–5 家願意參與的店家 |
| 店家 | 提供小額優惠或贈品、登記兌換次數、回饋意見 |

### 費用（新台幣，估計）

| 項目 | 估計 |
|---|---|
| 新區域的點位內容與故事（AI 起草、人工查證） | 10–20 萬 |
| 程式調整（AI 輔助） | 20–40 萬 |
| 主機（靜態網站，幾乎免費） | 約 0–1 萬 |
| 店家物料與 QR Code 立牌 | 5–10 萬 |
| 週末走讀活動 | 10–20 萬 |
| 問卷與數據整理 | 5–10 萬 |
| 專案協調 | 10–15 萬 |
| **合計** | **約 60–120 萬** |

店家的優惠由店家自行負擔。這筆經費規模小，可以由團隊自籌、商圈贊助，或市府用既有的推廣活動經費支應，不必另外編列大型預算。因為不需要帳號和後端，方案 D 沒有固定的年度伺服器費用。

### 驗證之後

- **數據好**：用驗證報告申請補助或尋求合作，進入方案 C（App＋帳號＋完整兌換），再擴大到其他區域。
- **數據普通**：調整玩法、點位或店家合作方式，換一個區再驗證一次。

## 為什麼選象山這條路線

- 政見規劃的三座登山觀光中心裡，「東象山」串的是信義商圈和台北 101，商圈、交通和觀光客都最多。登山觀光中心是政見中的規劃，還沒設立，所以示範路線先從捷運象山站和步道口出發，中心設立後再接上。
- 遊戲第一階本來就是四獸山（象、虎、豹、獅），角色、戰鬥、故事都能直接沿用，只要把 Demo 用的會場周邊點位，換成步道口和商圈的真實地點。
- 捷運象山站到登山口的距離短，好走、好推廣，也方便規劃「最後一哩路」。

- 臺北旅遊網景點 Open API（已接上）
- 四獸山親山步道路線、出入口與里程（大地工程處）
- 步道即時路況與封閉公告
- 文化資產／古蹟清單與座標（文化局）
- 示範路線各點位的實地 GPS 座標與照片（現場踏查）
- 首批合作店家名單與優惠內容（商業處、商圈發展協會）

## 100 天時程

| 期間 | 工作 | 產出 |
|---|---|---|
| 第 1–30 天 | 確認合作局處、資料授權與合作商圈；選定示範路線點位；安全評估；設計 App、帳號與兌換的後端；申請 Apple、Google 開發者帳號；**先預約第三方資安與無障礙檢測的時段** | 路線與點位清單、店家名單、系統設計 |
| 第 31–60 天 | 現場踏查校正座標、拍照；新地點的故事與問答撰寫、文化局審訂、英文翻譯；開發 App（背景定位、計步）、帳號、紀錄與兌換核銷 | 可內部試玩的 App |
| 第 61–90 天 | 資安、個資與無障礙檢測；在合作店家設置 QR Code 立牌（步道口的立牌要先取得設置許可，來不及就先放在店家和捷運站周邊）；用 TestFlight／Google Play 封閉測試邀請第一批市民試玩並修正 | 通過檢測的測試版 App |
| 第 91–100 天 | 擴大實地測試，搭配週末走讀活動；首批店家開始兌換「商圈信物」；開始匿名統計；同時送 Apple、Google 審核上架 | 實地測試數據、送審中的 App |

> App 上架要經過 Apple 和 Google 審核，時間和結果都不可控，所以 100 天的承諾是「App 完成並進入實地測試」，正式上架商店不列入 100 天內。測試期間，一般民眾仍可用手機網頁版體驗。

## 可行性檢視：哪些地方可能來不及

| 項目 | 風險 | 調整方式 |
|---|---|---|
| 起算時間 | 補助審查、合作備忘錄簽署都需要時間，不在團隊控制內 | 100 天從經費與合作確定後起算；前置作業期間先用自有資源做路線踏查和內容草稿 |
| 登山觀光中心 | 政見規劃中的設施，100 天內不一定設立 | 示範路線從捷運象山站和步道口出發 |
| 局處資料與審訂 | 跨局處協調、內容審訂常比預期久 | 先用已公開的開放資料（臺北旅遊網、文化資產資料）；審訂採分批送審，不等全部完成 |
| 步道即時路況 | 不一定有即時 API | 後台加上手動停用開關 |
| 第三方檢測 | 檢測機構要排程，報告也要時間 | 第 1–30 天就先預約；開發期間用 AI 和自動化工具先做一輪弱點掃描 |
| 現場立牌 | 步道與公有地設置要申請許可 | 先放合作店家和捷運站周邊，許可下來再補 |
| 店家招募 | 店家要看到玩家人數才有意願 | 首批只找一個商圈、約 5 家，由商圈發展協會協助 |
| App 上架 | 審核不可控 | 不列入 100 天承諾，用 TestFlight／Google Play 封閉測試做實地測試 |

## 用 AI 工具加速

《洋流》的 MVP 本身就是大量使用 AI 工具做出來的（見 README 的 AI 工具表）。100 天的工作也可以用同樣的方式加速，**AI 負責起草和重複性工作，人負責判斷、查證和審訂**：

| 工作 | AI 怎麼幫忙 | 人要做的 |
|---|---|---|
| 程式開發 | 用 AI 程式助理（例如 Claude Code）撰寫 App 包裝、後端、兌換核銷頁與自動化測試 | 架構決策、程式審查、資安把關 |
| 測試 | AI 產生測試案例，搭配 Playwright 自動化跑手機尺寸的完整流程 | 實地走路測試、判斷體驗是否順暢 |
| 地點故事與問答 | 從開放資料與文獻整理出故事和問答草稿 | 查證史實、文化局審訂、保留在地觀點 |
| 翻譯 | AI 初譯中英（之後日韓） | 母語者校對 |
| 美術 | AI 生成物品、守門獸和商圈信物的概念圖，維持 Roblox 方塊風 | 美術把關、統一風格、確認不侵權 |
| 配音與音樂 | AI 語音與配樂（MVP 已使用 Gemini TTS、Lyria） | 選角、調整語氣 |
| 資安初檢 | AI 輔助程式碼審查與弱點掃描 | 第三方正式檢測仍不可省 |
| 客服 | AI 整理常見問答，回答玩家和店家的基本問題 | 處理兌換爭議等例外狀況 |

AI 加速主要降低的是「內容、遊戲擴充、App 開發、後端」這幾項的人力時間，下面的預算已經把這部分算進去。**不能省的**是第三方資安檢測、文化局審訂、母語校對、實地踏查和店家溝通，這些都需要真人和實際到場。

## 三種方案比較

| | 方案 A：只做手機網頁 | 方案 B：只做 App | 方案 C：網頁＋App（建議） |
|---|---|---|---|
| 怎麼玩 | 用瀏覽器開網址就能玩，可加到主畫面 | 到 App Store／Google Play 下載 | 想試玩的人開網頁；要正式走路線、集章、兌換的人下載 App |
| 100 天開發費 | **約 220–370 萬** | **約 320–530 萬** | **約 340–570 萬** |
| 每年營運費 | **約 70–150 萬** | **約 85–185 萬** | **約 95–200 萬** |
| 100 天內可達成 | 正式上線 | App 完成、進入實地測試（上架商店時間不可控） | 網頁版正式上線；App 完成、進入實地測試 |
| 走路與定位 | 畫面關掉或切到背景，GPS 就停止，走路距離容易漏算；沒辦法讀手機的計步器 | 背景定位和手機內建計步器，記錄最準 | 網頁版同 A；App 版同 B |
| 防偽 | 難偵測模擬定位，商圈信物要靠現場 QR Code 等方式補強 | 可偵測模擬定位，交叉比對步數與 GPS | 兌換信物限定用 App，防偽同 B |
| 推播提醒 | iPhone 要先加到主畫面才收得到，支援度有限 | 完整支援（例如「附近有機緣」） | App 版完整支援 |
| 門檻 | 最低，不用下載，掃 QR Code 就玩 | 要下載安裝，部分人會因此放棄 | 先用網頁吸引人，再引導下載 App |
| 更新速度 | 改完立即生效 | 每次更新都要送審 | 網頁立即生效；App 要送審 |
| 適合 | 預算有限、先驗證大家願不願意走 | 重視紀錄準確與兌換防偽 | 想兼顧推廣的低門檻與兌換的可信度 |

方案 A 的費用不含 App 開發與 App 資安檢測，但多了以現場 QR Code 補強防偽的費用；方案 B 不需維護網頁版與做網站無障礙檢測；方案 C 兩邊共用同一套遊戲程式和後端，所以只比 B 多一點。

**建議方案 C**：手機網頁版的低門檻適合推廣、走讀活動和「靈界走走」，App 負責精準記錄走路和兌換商圈信物。下面的預算與年度營運成本都以方案 C 計算。

| 雲端主機與開發者帳號 | 後端與資料庫；Apple、Google 開發者帳號 | 5–10 萬 |
| 檢測 | 資安（含 App）、個資與網站無障礙檢測 | 35–55 萬 |
| 實地測試 | 測試用手機、測試者招募與試玩活動 | 10–20 萬 |
| 現場立牌 | 步道口、登山中心與合作店家，約 15 處 | 15–30 萬 |
| 推廣活動 | 週末走讀、合作店家宣傳 | 30–50 萬 |
| 專案管理 | 跨局處協調、店家聯繫、測試營運 | 20–30 萬 |
| **合計** | | **約 340–570 萬** |

說明：
- 比 MVP 多出最多的是「App 開發」和「帳號與後端」。要精準記錄走路和到訪，需要 App 的背景定位與計步；商圈信物要換成實體優惠，紀錄就不能只存在玩家手機裡。
- App 沿用現有的遊戲程式，用跨平台方式包裝成 iOS 和 Android，不必從頭重寫兩套，再加上 AI 程式助理，所以能在 100 天內完成。
- 和前一版估計（約 430–710 萬）相比，AI 加速大約省下兩成，主要在內容、遊戲擴充、App 與後端開發。
- 合作店家提供的優惠由店家自行負擔，不列入市府預算。

## 上線後的年度營運成本

商圈信物的兌換要由後端伺服器檢驗（一次性兌換碼、防止重複使用、帳號與紀錄保存），所以上線後每年都會有固定的營運成本。這部分不屬於 100 天的開發預算，需要有穩定的財源。可能的來源見下一節：補助計畫的營運經費、商圈與店家的合作費，或由市府提供既有的雲端主機分擔伺服器成本。

| 項目 | 內容 | 每年估計 |
|---|---|---|
| 伺服器與資料庫 | 帳號、紀錄與兌換檢驗的後端；依使用人數調整 | 10–30 萬 |
| 開發者帳號 | Apple 開發者計畫年費（Google 只需一次性註冊費） | 約 0.5 萬 |
| 系統維運 | 資安更新、配合 iOS／Android 與瀏覽器新版本調整、故障處理（AI 輔助測試與除錯） | 60–120 萬 |
| 內容更新 | 新增或更新地點、故事與商圈資料（AI 起草、人工審訂） | 15–30 萬 |
| 店家與玩家客服 | 兌換問題處理、店家聯繫 | 10–20 萬 |
| **合計** | | **約 95–200 萬／年** |

## 可能的合作方式

我們不打算直接走政府標案，而是以**申請補助**為優先，搭配和市府、商圈的合作。這樣團隊可以保有《洋流》的智慧財產權，也比較能照自己的步調發展。

| 方式 | 怎麼做 | 好處 | 要注意的 |
|---|---|---|---|
| **申請補助（優先）** | 以團隊或公司名義申請產業、文化、數位內容或創新研發類的補助，用來支付開發費 | 智慧財產權留在團隊；用途比標案彈性 | 補助通常要自籌部分經費、有結案報告；計畫的申請資格要先確認 |
| 和市府合作 | 簽合作備忘錄：市府提供開放資料、步道路況、推廣管道和既有主機，團隊負責開發與營運 | 不涉及採購，合作彈性大 | 市府不直接出錢，開發費要靠其他來源 |
| 商圈與店家合作費 | 商圈或店家付費加入「商圈信物」，依年費或兌換次數計算 | 後端營運費有穩定來源，也證明商圈願意買單 | 要先累積玩家人數，店家才有意願付費 |
| 政府標案（備選） | 市府編預算，公開招標委外 | 經費一次到位 | 程序繁瑣；採購契約預設常把成果的著作權歸機關，要在招標文件中明訂例外 |

### 補助方向

**創新不分年齡。** 《洋流》是一個由有經驗的創作者發起、結合 AI 工具做出來的作品，我們以團隊或公司的身分，申請不限年齡的補助：

- 台北市產業發展局的產業發展獎勵補助（以在台北設立的公司申請）
- 文化內容、數位內容類的開發補助（例如文化部、文化內容策進院的相關計畫）
- 觀光、地方創生類的補助計畫
- 中小企業創新研發類的補助（例如經濟部的 SBIR）

**和青年政策的關係**：這次政見的青年政策「本金、工具、舞台」（台北來加速）是給青年的資源，《洋流》不是要去申請它，而是可以成為青年的**舞台**：

- 讓青年用《洋流》參與市政實作：撰寫城市故事、規劃新路線、設計新的守門獸，對應圓夢計畫的「市政參與」。
- 和青年 AI 使用支持方案合作舉辦專題競賽，以《洋流》為題材，讓青年用 AI 工具創作在地文化內容。
- 讓有經驗的團隊和青年一起做，把開發 IP、營運和 AI 協作的經驗交給下一代，這就是跨世代的合作。

> 青年政策目前是政見，要等正式實施、公告辦法後才能合作；各補助計畫的名稱、資格與金額每年都會調整，申請前請以主管機關最新公告為準。

### 不論哪種方式都要談清楚

- **智慧財產權全部歸屬團隊**：世界觀、角色、四獸造型、遊戲程式，以及為合作新做的台北故事、問答、照片與路線資料，著作權都歸團隊。市府或合作單位取得**非專屬、永久的使用授權**，可用於推廣、導覽與觀光宣傳。原始碼由團隊保有，必要時可約定交由第三方託管。
- **資安與個資**：依個人資料保護法，只蒐集必要資料（帳號、到訪紀錄），不保存移動軌跡，資料存放在國內；App 依「行動應用 App 基本資安檢測基準」與 OWASP Mobile Top 10 檢測。
- **無障礙**：手機網頁版依「網站無障礙規範」檢測；範圍與限制見 README 的「MVP 的範圍與限制：無障礙」。

## 怎麼算成功

- 實地測試期間，示範路線的到訪人次與完成四獸靈門的人數
- 商圈信物的兌換次數與合作店家數
- 試玩問卷：玩家是否因此第一次走四獸山步道、是否更認識路線上的歷史

這些指標都用匿名統計，不保存玩家的移動軌跡。
