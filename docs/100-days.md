# 《洋流》市府上任 100 天：分區驗證

> 這份文件只放**市府上任第一天就能開始、100 天內真的做得到**的兩個方案：一個以手機網頁為主軸，一個以 iOS App 為主軸。分工、時程與金額都是團隊的估計。
>
> 帳號、後端兌換、Android App 與商店正式上架這些完整版的工作，要等補助核定或合作簽署、也要多個局處配合，不可能從上任第一天起算，所以另外放在 [docs/full-version.md](full-version.md)，當作驗證之後的下一步。

## 一句話

上任第一天就開始，選一個區、結合少數店家，讓市民真的走出門玩。100 天後用數據回答一件事：**這個做法值不值得擴大到全市。**

這和政見「先從代表性路線做示範，再逐步擴大到不同主題與區域」的推動藍圖一致。

## 怎麼判斷「第一天就能開始」

我們用四個條件重新檢視，兩個方案都符合：

| 條件 | 為什麼 |
|---|---|
| 從現有的遊戲出發 | 手機網頁版已經能玩；App 也是把同一套遊戲包裝起來，不從頭寫 |
| 不用等經費審查 | 補助審查、編列預算都要好幾個月，經費必須是團隊、商圈和市府既有經費當下就能出的 |
| 市府只需要少量人力 | 新團隊剛上任，局處還在交接；只需要一位專案窗口和商業處的店家支援，不必跨多個局處協調 |
| 不需要申請許可或第三方檢測 | 公有地立牌許可、正式資安檢測都要排程，100 天內不保證拿得到 |

## 兩個方案

| | 方案一：手機網頁為主軸 | 方案二：iOS App 為主軸 |
|---|---|---|
| 怎麼玩 | 掃 QR Code 用瀏覽器開，不用下載 | iPhone 用 TestFlight 安裝測試版 App；Android 和不想安裝的人用手機網頁版 |
| 要開發什麼 | 只換點位和內容，遊戲本身已經做好 | 把現有遊戲包裝成 iOS App，加上背景定位和手機內建計步器 |
| 走路紀錄 | 畫面關掉就停止記錄，走路距離容易漏算 | 畫面關掉也能記錄，計步準確 |
| 防偽 | 難偵測模擬定位，靠小額優惠控制風險 | 可以交叉比對步數和定位，比較可信 |
| 門檻 | 最低，掃了就玩 | 要先安裝 TestFlight 再裝 App，會流失一部分人 |
| 回答什麼問題 | 有沒有人玩、能不能帶人進商圈 | 再加上：App 的走路紀錄和防偽，值不值得投資完整版 |
| 費用（估計） | **約 55–95 萬** | **約 80–145 萬** |
| 適合 | 先用最低成本確認概念 | 想在 100 天後直接拿 App 的數據規劃完整版 |

兩個方案都在同一個區域、同樣的點位和店家，差別只在玩家用什麼玩。方案二不做帳號和後端，紀錄一樣存在玩家手機；正式上架 App Store 也不列入 100 天（見下方可行性檢視）。

## 人力：這是能不能做成的關鍵

專案的成敗在資源。目前《洋流》只有發起人一個人，而且**發起人有正職工作**，沒有時間管理團隊或跑現場，只能用下班時間**配合更新程式**。所以兩個方案的前提是：**市府主責營運與管理，發起人負責程式。**

### 發起人負責的部分（下班時間，搭配 AI）

- 依市府提供的點位、店家與活動資料，更新遊戲程式和內容；方案二另外包裝 iOS App。
- 用 AI 起草地點故事、問答、英文翻譯和物品美術，交給市府查證。
- 修正試玩期間回報的問題。

這些都能在家用電腦完成，靠 AI 工具控制在下班時間的負荷內。發起人**不負責**管理人員、跑現場、聯繫店家或辦活動。

### 市府負責的部分

| 工作 | 誰來做 |
|---|---|
| 專案管理：排進度、協調各方、收集回報轉給發起人 | 市府指定一位專案窗口 |
| 招募與聯繫店家、談優惠與兌換規則、回收兌換登記表、處理店家問題 | 產業發展局商業處人員（店家的部分一定要由市府人員支援） |
| 實地踏查、校正點位座標與照片、設置與維護店內立牌 | 市府人員，或由市府委託的現場營運人員 |
| 辦週末走讀、帶隊、現場協助市民遊玩 | 市府人員或委託人員，可搭配志工、青年參與 |
| 回覆市民的問題、問卷與數據整理、驗證報告 | 市府專案窗口 |

**沒有市府的人力支援，這兩個方案都不成立。**

### 能借力的地方

- **商圈發展協會**：協助商業處媒合店家。
- **里辦公處、區公所**：在地宣傳、活動場地。
- **志工或青年**：週末走讀的帶隊和協助，也可以呼應政見中讓青年參與市政實作的方向。

### 為什麼範圍要收這麼小

- **只做一個區、3–5 家店家、2 場走讀**：市府初期能投入的人力有限，先小規模驗證。
- **方案二只做 iOS**：背景定位是 Apple 和 Google 都審得最嚴的權限，發起人只有下班時間，兩邊的審查和實機測試同時顧會被拖住；iOS 可以直接用手上的 Mac 和 iPhone 開發測試。
- **不做帳號和後端**：少了伺服器，就少了維運、資安和客服的負擔。

開發人力增加了（例如多一位開發者），才考慮加第二個區或 Android App。

## 範圍（兩個方案共通）

| | 做 | 不做（留給完整版） |
|---|---|---|
| 區域 | 信義區象山一帶（四獸山步道＋信義商圈），8–10 個公共、好走的點位 | 其他區域、需要許可的步道立牌 |
| 店家 | 3–5 家願意參與的店家，提供小額優惠或贈品 | 大規模招募、店家後台 |
| 帳號與兌換 | 不做帳號；用現有的兌換畫面（會動的圖案＋當下時間＋用過蓋章），店家用登記表記錄兌換次數 | 伺服器紀錄、一次性兌換碼、核銷系統 |
| 內容 | 中文；英文用 AI 初譯、人工快速校對 | 日韓語、文化局正式審訂 |
| 安全 | 人工確認步道狀況，只選白天的公共點位 | 即時路況串接 |
| 個資 | 不收集個資，紀錄只存在玩家手機 | 帳號與雲端同步 |

## 時程

| 期間 | 方案一：手機網頁 | 方案二：iOS App 另外加上 |
|---|---|---|
| 第 1–14 天 | 市府指定專案窗口；商業處聯繫商圈與店家、確認優惠；發起人提出點位建議 | 申請 Apple 開發者帳號；開始把遊戲包裝成 iOS App |
| 第 15–45 天 | 發起人把 Demo 點位換成新區域、用 AI 起草故事與問答；市府查證內容、現場校正座標、製作店內 QR Code 立牌 | 加上背景定位和計步器、實機測試 |
| 第 46–60 天 | 開放市民試玩 | 送 TestFlight 外部測試審查；通過後開放第一批測試者 |
| 第 61–90 天 | 辦 2 場週末走讀；店家開始兌換 | 走讀時協助參加者安裝 App |
| 第 91–100 天 | 市府整理數據與問卷，寫驗證報告 | 比較 App 和網頁玩家的走路紀錄與兌換數據 |

## 可行性檢視：還是可能卡住的地方

| 風險 | 調整方式 |
|---|---|
| 市府窗口在上任初期還沒指定 | 窗口指定前，發起人先用公開資料準備點位建議和故事草稿；現場工作從窗口指定後開始 |
| 14 天內找不到店家 | 首批只要 3 家，由商業處透過商圈發展協會媒合；找不到時先用景點和走讀活動開始，店家在第 45 天前補上 |
| 現場座標不準 | 每個點位都由市府人員實地走過、校正，回報給發起人更新 |
| 天候（颱風、豪雨） | 走讀活動預留備用日期；點位都在白天的公共區域 |
| 玩家人數太少 | 結合走讀活動、商圈和里辦公處的社群宣傳；問卷同時問「為什麼沒來」 |
| 兌換有人作弊 | 優惠設計成小額；店家登記表可以看出異常次數 |
| （方案二）TestFlight 外部測試要經過 Apple 審查，背景定位權限審得特別嚴 | 第 46 天就送審，預留兩週，權限用途寫清楚；萬一卡住，先用手機網頁版開放，App 補上後再加入 |
| （方案二）App Store 正式上架審核不可控 | 不列入 100 天承諾；TestFlight 一個 App 最多可邀請 10,000 名測試者，驗證規模足夠 |
| （方案二）Android 使用者 | 用手機網頁版參加；Android App 留到完整版，避免一個人同時顧兩邊的審查和實機測試 |

## 用 AI 工具加速

《洋流》的 MVP 本身就是大量使用 AI 工具做出來的（見 README 的 AI 工具表）。驗證期間也用同樣的方式，**AI 負責起草和重複性工作，人負責判斷、查證和實地走過**：

| 工作 | AI 怎麼幫忙 | 人要做的 |
|---|---|---|
| 換點位與程式調整 | 用 AI 程式助理（例如 Claude Code）改點位資料、調整介面、跑自動化測試 | 程式審查、手機實測 |
| （方案二）iOS App 包裝 | AI 程式助理撰寫包裝、背景定位與計步的程式 | 實機測試、送審 |
| 地點故事與問答 | 從開放資料與文獻整理出故事和問答草稿 | 查證史實、保留在地觀點 |
| 翻譯 | AI 初譯英文 | 人工校對 |
| 物品美術 | AI 生成店家物品概念圖，維持 Roblox 方塊風 | 美術把關、統一風格 |
| 數據整理 | 整理問卷和兌換登記表 | 判斷結論、寫建議 |

不能省的是實地踏查、校正座標和跟店家當面溝通，這些由市府人員負責。

## 費用（新台幣，估計）

| 項目 | 方案一：手機網頁 | 方案二：iOS App | 誰負責 |
|---|---|---|---|
| 程式調整（AI 輔助） | 15–30 萬 | 15–30 萬 | 發起人 |
| iOS App 包裝、背景定位與計步（AI 輔助） | — | 20–35 萬 | 發起人 |
| Apple 開發者帳號與測試用 iPhone | — | 5–10 萬 | 發起人 |
| 新區域的地點故事與問答（AI 起草、人工查證） | 10–15 萬 | 10–15 萬 | 發起人起草、市府查證 |
| 主機（靜態網站） | 約 0–1 萬 | 約 0–1 萬 | 發起人 |
| 現場營運（踏查、立牌、走讀帶隊，市府人員或委託） | 15–25 萬 | 15–25 萬 | 市府 |
| 店家物料與店內 QR Code 立牌 | 5–10 萬 | 5–10 萬 | 市府 |
| 週末走讀活動 | 5–10 萬 | 5–10 萬 | 市府 |
| 問卷與數據整理 | 3–5 萬 | 5–8 萬 | 市府 |
| 專案窗口、商業處的店家聯繫 | 既有人力 | 既有人力 | 市府 |
| **合計** | **約 55–95 萬** | **約 80–145 萬** | |

- 發起人負責的開發費用：方案一約 25–45 萬、方案二約 50–90 萬，由團隊自籌或商圈贊助，不等補助或預算審查。
- 市府負責的現場與活動費用約 30–50 萬，可以用既有的推廣活動經費或商圈贊助支應；專案窗口和商業處人員用既有人力，不另外計費。
- 店家的優惠由店家自行負擔。
- 兩個方案都不需要帳號和後端，沒有固定的年度伺服器費用；方案二每年多一筆 Apple 開發者年費（約 3,300 元）。
- 驗證期間就可以開始準備補助申請，100 天後用驗證報告去申請，作為完整版的經費。

## 怎麼算成功

| 問題 | 怎麼看 |
|---|---|
| 大家會不會因為遊戲走出門？ | 到訪人數、完成四獸靈門的比例、走路距離 |
| 會不會帶人進商圈？ | 各店家的兌換次數、店家主觀感受 |
| 有沒有認識在地文化？ | 城市故事（讀完並淨化守門街貓）的完成率、試玩問卷（是否第一次走這條步道、是否記得某個故事） |
| 會不會再回來？ | 回訪人數、有沒有人問下一區 |
| （方案二）App 值不值得？ | App 和網頁玩家的走路紀錄完整度、安裝流失率、兌換可信度 |

這些指標都用匿名統計，不保存玩家的移動軌跡。

## 驗證之後

- **數據好**：用驗證報告申請補助、和市府簽合作備忘錄，進入 [完整版](full-version.md)（帳號、後端兌換、Android App、商店上架），再擴大到其他區域。
- **數據普通**：調整玩法、點位或店家合作方式，換一個區再驗證一次。
- **數據不好**：停在這裡，損失只有幾十萬，不會浪費大型預算。

## 智慧財產權

不論驗證或之後的完整版，《洋流》的世界觀、角色、遊戲程式（含 App），以及為驗證新做的地點故事與問答，著作權都歸屬團隊。商圈、店家或市府取得非專屬的使用授權，可用於推廣與宣傳。合作方式的細節見 [完整版規劃](full-version.md#可能的合作方式)。
