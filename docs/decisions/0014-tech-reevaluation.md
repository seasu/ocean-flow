# 0014 技術路線重新評估

- 日期：2026-11-06
- 狀態：待定
- 來源：Seasu 在 D4 要求重新評估是否改用 Flutter 或其他技術

## 提案

建議**維持網頁技術 + Capacitor**（0003、0010），不重寫。

| 面向 | 網頁 + Capacitor | Flutter 重寫 | Godot／Unity 重寫 |
|---|---|---|---|
| 既有成果 | 全部保留 | 幾乎全部重寫；自寫 WebGL 方塊世界沒有成熟的 Flutter 3D 對應 | 全部重寫 |
| AI 在雲端開發與 QA | 能直接跑遊戲、截圖、自動測試 | 雲端裝不了 Flutter（pub.dev 與下載伺服器被擋），每次驗證都要等 Actions | 同樣裝不了；Unity 還有授權費，工作多在編輯器內 |
| 免安裝網頁版 | 保留 | Flutter Web 首次載入重、手機偏慢 | 可匯出但很重 |
| 熱更新 | 已自建、免費 | 要用 Shorebird，超過免費額度要付費 | 要自己做 |
| 背景 GPS | 已接好 | 成熟外掛可用 | 要寫原生外掛 |
| 效能 | 目前規模夠用；風險是耗電發熱 | 介面最順 | 3D 最好 |

## 何時重新評估

真機無法維持穩定畫面或明顯發熱；要做 AR、多人即時對戰等重度原生功能；有專職工程師加入。屆時遊戲引擎（Godot／Unity）會比 Flutter 合適。
