## 1. 一句話

**《洋流》是一款走出去才玩得到的手機網頁遊戲：玩家在真實台北走到特定地點，觸發「機緣」，在靈界裡喚醒山的靈脈，同時認識這個地方真正的樣子。**

黑客松提案句：用《洋流》讓年輕人先在手機上走一遍台北的文化徑與山林徑，再真的去走。

## 2. 背景與目標

### 2.1 參賽情境

- 活動：市政debug松（puma.taipei/hackathon），選 **第 7 題「自訂主題」**。
- 題目：**[洋流] 透過遊戲讓大家了解台灣的美**。
- 呼應政見：**台北文化徑×山林徑**（文化徑串連城市記憶與產業遺跡；山林徑在象山、劍潭、貓空設登山觀光中心，提供數位導覽）。
- 時程：10/18 報名截止 → 10/23 晚上線上提案 → 10/24 現場實作一天並 Demo，**作品必須能現場操作**。
- 現場地點：台北市中正區北平東路 30 號。

### 2.2 產品目標

| # | 目標 | 怎麼算達成 |
|---|---|---|
| G1 | 讓玩家認識台北山林的美，從四獸山開始 | 玩家完成一輪後，能說出四座山的名字與各一個特色 |

- 全台灣地圖（只做台北四獸山）
- Roblox 版本
- 付費與商業化

## 4. 世界觀摘要

（詳見 `production-package-v1.md`）

- **核心訊息**：人類正在重新學會感知世界。
- **品牌句**：山有脈，海有流，人亦有自己的道。／走出去，遇見你的機緣。
- **現世 × 靈界**：兩個世界從未分離，只是人類失去了感知能力。
- **啟流**：台灣是第一個重新啟流的地方，山脈甦醒、海流共鳴，城市裡出現靈界的回聲。
- **機緣**：在現世走到某處，靈界裡就會有東西回應你。這是遊戲的核心機制。
- **風格**：現代台灣中的第二世界，Neo Xianxia。不是古裝宮廷、不是武俠打鬥、不是霓虹賽博。

### 4.1 台北：第一個啟流城市

啟流初期，人們最先注意到的不是深山，而是台北城市邊緣的四座低山。當四個節點在同一夜出現同步異象，研究者第一次確認：**城市本身，也存在流。**

這讓《洋流》不是「去山區才有靈氣」，而是**都市也有自己的靈脈**。這對產品很重要，因為玩家平常就在城市裡。

### 4.2 第一階段故事：四獸靈門

四獸山（象山、虎山、豹山、獅山）位在台北信義區，就在城市旁邊、交通方便，能直接俯瞰台北盆地與台北 101。在《洋流》裡，四座山不是四個普通景點，而是台北「城市之流」與「山之流」交界形成的**四個守門節點**，合稱「四獸靈門」。

| 靈門 | 對應山 | 象徵 |
|---|---|---|
| 象門 | 象山 | 穩定、記憶、承載 |
| 虎門 | 虎山 | 行動、勇氣、爆發 |
| 豹門 | 豹山 | 敏捷、感知、身法 |
| 獅門 | 獅山 | 威勢、領導、宗門氣運 |

玩家不是去「打卡四座山」，而是完成一段四段式的現世修行：

```
第一印：象 → 第二印：虎 → 第三印：豹 → 第四印：獅
   → 四獸共鳴 → 開啟「台北靈門」
```

### 4.3 IP 與現實事件的界線

「台北大洋流」目前也是市長選舉的活動名稱。《洋流：起源》維持**獨立 IP**：

- 台北是第一個「啟流城市」，四獸山是重要靈脈節點。
- 現實事件可以是「時代背景靈感」，但**不把候選人、政黨、競選活動寫進遊戲 lore**。
- 遊戲把「洋流」解釋成人與土地、城市、山海之間的流動，不被一場選舉綁住。

## 5. 核心體驗

### 5.1 遊戲迴圈

```
走到現實中的地點
   → 手機感應到機緣（震動、光紋、鐘聲）
   → 進入靈界畫面：在該道靈門取印（短互動）
   → 獲得一枚印，世界往靈界多偏一層
   → 跳出景點小卡：真實照片＋簡介＋步道資訊
   → 地圖上亮起下一個機緣方向
```

### 5.2 一輪遊玩的流程

1. **開場**（約 30 秒）：簡短世界觀動畫，旁白取自概念片，可跳過。
2. **選角**：藍色款「阿流」或橘色款「阿汐」（見第 8 節）。
3. **探索**：地圖顯示下一道靈門的大致方向，不顯示精確位置，鼓勵玩家抬頭看路。依序為象→虎→豹→獅。
4. **觸發機緣**：進入靈門範圍後，畫面出現流動光紋，按「感知」開始取印。
5. **取印**：約 10–20 秒的短互動（例如沿著光脈畫線、按住感知讓靈光聚集），完成後該靈門的靈獸現身，獲得一枚印（第一印至第四印）。
6. **景點小卡**：靈獸現身後，畫面下方滑出一張小卡。
7. **四獸共鳴**：四印集齊後，四座山在靈界同時亮起，開啟「台北靈門」，顯示「下一處靈脈：大屯／陽明」。

### 5.3 景點小卡設計原則

Seasu 指定：畫面要能看到景點介紹，**但不要太搶視覺**。

- 預設收合成一條細長的卡片（景點名＋一行介紹），貼在畫面底部，不擋住靈獸。
- 點一下展開：2–3 張照片（橫向滑動）、100 字內的介紹、步道入口、建議路線長度。
- 半透明深藍底、白字，與靈界色調一致。
- 每張照片標示來源（開放資料授權要求，待確認）。
- 所有看過的小卡收進「台北山林圖鑑」，之後可以再看。

## 6. 第一階段內容：四獸山

### 6.1 四道靈門（四個機緣點）

| 順序 | 靈門 | 現實地點 | 象徵 | 介紹重點（待開放資料補齊） |
|---|---|---|---|---|
| 第一印 | 象門 | 象山 | 穩定、記憶、承載 | 俯瞰台北 101 與信義區、六巨石 |
| 第二印 | 虎門 | 虎山 | 行動、勇氣、爆發 | 虎山溪、生態步道 |
| 第三印 | 豹門 | 豹山 | 敏捷、感知、身法 | 較安靜的林間步道 |
| 第四印 | 獅門 | 獅山 | 威勢、領導、宗門氣運 | 山上的廟宇與石階 |

靈獸的造型（方塊風）尚待美術設計，方向是莊嚴、帶點神秘，各自呼應上表的象徵。

四獸山位在信義區東南，從信義象山站可步行抵達步道入口（待確認各入口位置）。

### 6.2 Demo 版：在會場附近模擬四獸山

10/24 現場無法帶評審去爬山，所以 Demo 版把四個機緣點**模擬在會場（北平東路 30 號）周邊步行可到的安全公共地點**：

- 選點原則：人行道寬、有人潮、不需穿越大馬路、白天晚上都安全、不進入私人或管制區域。
- 每個模擬點對應一座山，觸發後顯示的是**真實四獸山**的照片與介紹。
- 實際選點由「手機網頁遊戲原型」那邊決定，並記錄在原型的設定檔中。
- 另提供**室內 Demo 模式**：不靠 GPS，用地圖上點選或網址參數直接觸發機緣，避免現場 GPS 不準或評審沒時間走動。

### 6.3 正式版定位

正式版改用四獸山步道上的真實座標，觸發半徑約 30–50 公尺（待實測），只放在步道或觀景台等公開位置。

## 8. 角色與美術

### 8.1 角色

依 `ocean-flow-origin/character-ref/` 的角色設定圖（Roblox 風格方塊角色）：

| 角色 | 設定圖 | 定位 |
|---|---|---|
| 阿流 | 藍色款（有／無耳機兩版） | 主角，預設玩家角色 |
| 阿汐 | 橘白款 | 夥伴，可選為玩家角色 |

另有四色系列展板（`four-colors/`），可作為之後的角色換色或其他玩家造型。

### 8.2 美術方向

- **方塊風、低多邊形**，靠近 Roblox 的遊戲感，讓玩家一看就知道這是遊戲。
- 色調依製作包：現世是灰藍與自然光，啟流時出現流動光紋，靈界是深藍、青綠、金白。
- 四隻靈獸要莊嚴、帶點神秘，不要太卡通、不要太幼齒。
- 景點照片保持真實，與方塊風的靈界形成「現世 × 靈界」對比。

### 8.3 禁止事項

沿用製作包 6.2：不要古裝宮廷感、不要武俠打鬥、不要俗豔霓虹、**不要選舉宣傳視覺、不要使用政治人物或政黨元素**。

## 9. 聲音

- 旁白：已試過多種中文與英文老者聲線（`voice-tests/`），開場沿用定案版本。
- 音樂：空靈、紀錄片感開場，啟流時情緒擴張；不要熱血戰鬥或夜店電子。
- 音效：鐘聲、山林風聲、靈脈低頻共鳴、光紋 shimmer。
- 預設可靜音，戶外使用時不吵到別人。

## 10. 技術規格

| 項目 | 規格 |
|---|---|
| 平台 | Mobile Web（直式為主，橫式也可玩） |
| 前端 | 純 HTML＋JavaScript（ES modules），WebGL 方塊渲染，不需建置（沿用 PR #1 原型架構） |
| 定位 | 瀏覽器 Geolocation API；需要 HTTPS；拒絕授權時自動切到室內 Demo 模式 |
| 資料 | 開放資料先離線抓取存成靜態 JSON，Demo 時不依賴外部 API；照片以連結載入，失敗時顯示文字版小卡 |
| 部署 | GitHub Pages（原型已設定 workflow） |
| 效能 | 中階手機維持 30fps 以上；首次載入 5 秒內可開始 |
| 存檔 | 瀏覽器本機儲存，沒有伺服器 |
| 隱私 | 位置只在手機上比對距離，不上傳、不記錄 |

## 12. 安全

- 機緣點只放在公開、安全、人多的地點，不放在馬路中間、水邊、懸崖或私人土地。
- 走路時不需要一直盯著螢幕：觸發時用震動與聲音提醒。
- 首次開啟顯示提醒：「注意周遭環境，不要邊走邊看手機」。
- 夜間或天候不佳時，提示玩家改用室內模式（P2）。

## 13. Demo 腳本（10/24，約 5 分鐘）

1. **30 秒**：說痛點。台北有很好的近郊山林，但年輕人不知道、也沒理由去。
2. **30 秒**：開場動畫，帶出世界觀。
3. **3 分鐘**：用室內 Demo 模式依象→虎→豹→獅觸發四道靈門，每點展示取印互動與景點小卡；若時間與天氣允許，帶評審到會場外實際走一個模擬點。
4. **30 秒**：四獸共鳴、開啟台北靈門的收尾畫面，說明資料來自台北市開放資料，對應「文化徑×山林徑」的數位導覽。
5. **30 秒**：下一步。擴充到劍潭、貓空、大稻埕、北投，並加上多語。

## 17. 全球願景

> **《洋流》從台灣被發現，但不屬於台灣。它屬於整個世界。**

台灣不是《洋流》的全部，而是**人類第一次完成「啟流」紀錄的地方**。從台灣開始，世界各地陸續有人感知到自己的山、海、城市、文化與生命之流。《洋流：起源》的意義是：這是一切開始被人類看見的地方。台灣因此不會被弱化，而是整個 IP 的「原點」。

### 17.1 系列架構

| 作品 | 地區 | 主題 |
|---|---|---|
| 《洋流：起源》 | 台灣 | 第一個被完整記錄的啟流地區 |
| 《洋流：彼岸》 | 日本／東亞 | 不同文明對「流」有不同理解 |
| 《洋流：萬流》 | 全球 | 不同流派、宗門、文化開始交會 |

### 17.2 每個文化用自己的語言描述「流」

《洋流》不是把「台灣式修仙」或中國修仙世界觀套到全球。統一全球的不是「修仙」這個詞，而是「流」。

| 地區 | 對「流」的詮釋 |
|---|---|
| 台灣 | 山海、靈脈、宗門 |
| 日本 | 山岳信仰、神社、火山、森林 |
| 韓國 | 山城、古寺、山神文化 |
| 冰島 | 火山、冰川、地熱 |
| 美國西部 | 峽谷、荒漠、大河 |
| 歐洲 | 古城、森林、石陣、山脈 |

人類對它有不同的名字：氣、靈、神性、自然之力、生命力、土地記憶、共鳴、意識場。《洋流》提出一個假說：**也許不同文明一直都在描述同一種現象。**

### 17.3 玩家的世界修行歷程

玩家累積的不是景點徽章，而是「我的世界修行歷程」。每個地區有自己的流印：

| 年份（願景） | 地區・流印 |
|---|---|
| 2027 | 台灣・四獸靈門 |
| 2028 | 日本・富士流印 |
| 2029 | 冰島・火山流印 |
| 2030 | 美國・峽谷流印 |

對第一階段的影響：四獸靈門的四枚印，在資料設計上要能當作玩家「修行歷程」的第一筆紀錄，之後各地流印接在同一條歷程上（P2，黑客松不實作）。

### 18.1 現世 × 靈界的雙平台

## 19. 開發順序：影片先行

《洋流》是一個世界觀、跨平台產品與長期 IP，直接做遊戲容易遇到兩個問題：大家腦中的想像不一致，以及開發成本高、驗證慢。所以順序是**先做世界觀影片，再做遊戲**。影片是「可觀看的世界觀文件」，同時是美術、遊戲設計、合作簡報與 AI 生成的母參考。

### 19.0 AI-first 製作流程

原始規劃的整體順序：

```
World Bible → 90 秒 Trailer → Visual Bible → Roblox Alpha → Mobile Web MVP
```

因為黑客松需要可現場操作的作品，目前實際順序把 **Mobile Web MVP 提前到 Roblox Alpha 之前**（四獸靈門原型）。Roblox Alpha 留到黑客松之後。

影片部分以 AI 工具分工：

| 工作 | 工具類型 |
|---|---|
| 世界觀、旁白、分鏡、鏡頭設計、Prompt | 對話式 AI |
| 角色、台灣山海、宗門、靈界異象、啟流畫面 | 圖像生成 |
| 關鍵畫面轉成動態鏡頭 | AI Video（本專案實際改用 JS 動畫製作，見 `film-js/`） |
| 繁中旁白 | AI Voice（試音見 `voice-tests/`） |
| 東方氛圍＋現代感＋神秘感的配樂 | AI Music |
| 剪輯與節奏整合 | 剪輯軟體 |

概念片結尾的鉤子：**這不是台灣的故事。這只是起源。**（呼應第 17 節全球願景。）

### 19.1 三支影片

| 影片 | 長度 | 用途 | 重點 | 現況 |
|---|---|---|---|---|
| 世界觀概念片 | 90 秒～2 分鐘 | 建立 IP 形象、對齊團隊與合作對象 | 台灣、山海、啟流、現世與靈界、玩家是新世代修行者、「這只是起源」 | 已有 v1／v2（`film-v1/`）與 JS 動畫版（`film-js/`） |

| Alpha／原型體驗片 | 30～90 秒 | 用早期內容驗證玩法 | 一個實際的跨世界任務，例如四獸山 → 回靈界解鎖事件 | 可在黑客松原型完成後錄製 |
